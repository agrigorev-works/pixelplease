# Рекомендации по SEO и LLM-индексации

Дата аудита: 2026-07-04. Основано на разборе `index.html`, `public/robots.txt`, `public/sitemap.xml`, `public/llms.txt`, `public/site.webmanifest`, `docs/seo-proposal.md` и логики наполнения страницы из `src/main.ts` / `src/interface-copy.ts`.

## Итог

База уже сильная: title, canonical, OG/Twitter-карточки, `FAQPage` + `SoftwareApplication` schema, `robots.txt`/`sitemap.xml`, `llms.txt`, статичный FAQ в HTML.

Две главные проблемы:

1. **Ключевой контент страницы — H1 и вводный абзац — в статике пустой** и появляется только через JS. LLM-краулеры (GPTBot, ClaudeBot, PerplexityBot, CCBot) JS не исполняют и не видят ни заголовка, ни описания продукта.
2. **Сайт — одна страница**, что физически ограничивает охват ключевых кластеров из `docs/seo-proposal.md`.

## Быстрые победы (мало усилий, заметный эффект)

1. **Пререндерить H1 и интро-текст в статичный HTML.** Сейчас в `index.html` — `<h1 aria-label=""><span></span><span></span></h1>`, и `.intro-copy` пустой: текст вставляет `main.ts` из `UI_COPY`. Googlebot отрендерит (со второй волной индексации), LLM-краулеры — нет. Вписать «pixel please» и intro-копию прямо в разметку безопасно: JS перезапишет те же строки (гидрация идемпотентна). Единственное самое важное изменение для LLM-индексации.

2. **Зарегистрировать Google Search Console и Bing Webmaster Tools, отправить sitemap.** В seo-proposal помечено «after final domain» — домен `pixelplease.tools` уже финальный и живой. Bing особенно важен: им питаются ChatGPT Search и Copilot.

3. **Добавить слово «free»** в title/description и видимый текст. Инструмент бесплатный, но слово нигде не встречается, а «free pixel font generator» — очевидный высокочастотный вариант запроса.

4. **Дополнить SoftwareApplication-схему:** `"offers": {"@type": "Offer", "price": "0", "priceCurrency": "USD"}` — без `offers` или `aggregateRating` Google не показывает rich result для SoftwareApplication. Цена 0 — факт и не нарушает правило «не добавлять невидимые утверждения», если «free» появится в видимом тексте. Также добавить `featureList` и `screenshot`.

5. **Проверить, что CDN/WAF не блокирует AI-ботов.** Cloudflare с 2025 года блокирует AI-краулеров по умолчанию на новых зонах; у других хостингов бывают похожие WAF-правила. `robots.txt` разрешает всё, но блок на уровне CDN его перекрывает. Проверить по логам или запросом с User-Agent `GPTBot`/`ClaudeBot`.

6. **Автоматизировать `lastmod` в sitemap.** Сейчас захардкожено `2026-06-25`. Штамповать дату при сборке (небольшой node-скрипт по аналогии с `scripts/check-og-image.mjs`) — свежесть влияет на частоту переобхода у поисковиков и AI-краулеров.

## Среднесрочно

7. **Достроить запланированные секции «How it works» и «What you can export».** Они есть в `docs/seo-proposal.md` (пункты 4–5 структуры первой страницы), но в `index.html` реализован только FAQ. Это статичный, насыщенный ключами контент («convert font to pixel font», «TTF export»…), который увидят и не-JS краулеры. Пошаговый «How it works» — формат, который LLM охотно цитируют в ответах.

8. **`llms-full.txt` и синхронизация `llms.txt`.** Файл отличный и следует llmstxt.org. Два улучшения: добавить `llms-full.txt` с более полным содержимым (конвенция предусматривает) и учесть, что список семейств шрифтов в `llms.txt` захардкожен — при изменении набора шрифтов он разойдётся с реальностью (можно проверять скриптом в `verify` по `public/fonts/google/`).

9. **Редирект www → apex.** Canonical указывает на apex, аналитика допускает `www.pixelplease.tools` — убедиться, что на хостинге настроен 301 с www, иначе возможен дубль-хост.

10. **`<link rel="preload">` для дефолтного Merriweather** — ускорит первый осмысленный экран; Core Web Vitals — ранжирующий фактор, шрифты уже вендорены локально.

## Стратегический рост (главный рычаг)

11. **Статичные лендинги под длинный хвост.** Один URL не может ранжироваться по всем кластерам из proposal. Уже вендорено ~13 семейств демо-шрифтов — каждое может стать отдельной пререндеренной страницей («Pixel Inter», «Pixelated Merriweather»…) с уникальной картинкой-превью результата, парой абзацев и ссылкой в инструмент с предвыбранным шрифтом. Плюс страница-гайд «How to make a pixel font». Важно: чтобы не выглядеть doorway-страницами, каждой нужны уникальные превью и текст, и все — в sitemap. Vite поддерживает multi-page build, архитектуру ломать не придётся.

12. **Внешние сигналы, которые читают и LLM:** Product Hunt, AlternativeTo, каталоги дизайн-инструментов. LLM-рекомендации («посоветуй pixel font generator») сильно опираются на такие агрегаторы в обучающих данных и при поиске. Публичный GitHub-репозиторий с «Common Questions» в README уже есть — правильный ход, LLM активно индексируют GitHub.

## Документация

Реализованный title («Pixel Font Generator - Convert TTF/OTF to Pixel Fonts | pixelplease», ключи впереди) — лучше, чем «best default» из `docs/seo-proposal.md` (бренд впереди, а бренд пока никто не ищет). Обновить proposal, чтобы он отражал фактическое решение.
